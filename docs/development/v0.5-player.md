# 留文 v0.5 播放器实施记录

日期：2026-07-23

## 本轮结论

`留文_v0.5_播放器组件最终实施方案.md` 的主链路已落地。结果页现在使用 B 站官方 iframe 播放器，核心观点与逐字稿中的时间戳统一定位到同一个播放器。

## 已完成

- 新增独立播放器组件、B 站 URL 构造工具和统一 seek 状态 Hook。
- 首次加载固定 `autoplay=0`；点击时间戳后切换为 `autoplay=1`。
- 每次点击都会增加重载版本，因此连续点击同一个时间点也会重新定位。
- 时间统一向下取整、最小为 0，并在已知视频时长时限制在时长范围内。
- BV 号使用 `^BV[0-9A-Za-z]{10}$` 校验，播放器地址固定为 `player.bilibili.com`。
- 支持 B 站链接 `?p=` 多 P 参数，后端选择对应 CID、分 P 时长和来源地址。
- 播放器下方始终提供“在哔哩哔哩打开当前时间”降级入口。
- 旧任务读取时自动补齐 `video` 对象；BV 号无效时安全降级，不影响内容浏览和导出。
- 增加 `frame-src 'self' https://player.bilibili.com` CSP。
- 增加播放器加载态、移动端布局和减少动态效果适配。

## 数据结构

新任务结果保留原有扁平字段，同时新增：

```json
{
  "video": {
    "platform": "bilibili",
    "bvid": "BVxxxxxxxxxx",
    "page": 1,
    "sourceUrl": "https://www.bilibili.com/video/BVxxxxxxxxxx?p=1",
    "title": "视频标题",
    "author": "作者",
    "duration": 600
  }
}
```

保留扁平字段是为了兼容已有前端、下载接口和历史数据。

## 验证项目

- Node URL/参数单元测试：BV 校验、分 P、时间归一化、播放器与站外链接。
- Python 后端测试：多 P 解析、对应 CID 与分 P 时长选择、v0.4 证据和保存能力回归。
- `vinext build`。
- ESLint；仅保留项目原有两个 `img` 性能建议，无错误。
- 本地浏览器验收：首次不自动播放、点击时间戳定位、重复点击重载、逐字稿与总结共用定位状态、CSP 响应头。

## 明确限制

- 不跨域读取播放器内部当前进度，不做播放进度与页面的双向同步。
- 浏览器可能拦截 iframe 自动播放；用户可在播放器内点击播放，或使用站外降级入口。
- B 站播放器的可用性仍受视频权限、地区、登录状态和 B 站策略影响。
